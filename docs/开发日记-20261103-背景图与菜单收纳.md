# 开发日记：给 Web 终端加一层背景图（v1.0.15）

**项目：wsstunnel（WebSocket 反向 Shell 中继）　版本：v1.0.14 → v1.0.15**
**日期：2026-11-03**

## 一、需求

> 增加背景图片配置功能，可调整模糊度、亮度和选图片，可以选本地也可用网页 URL，背景图片要缓存，下次不用重新拉。

拆成四件事：

1. 能选图：本地文件 + 网页 URL 两种来源；
2. 能调参：模糊度、亮度实时生效；
3. 要缓存：URL 图第一次拉完就落盘，**刷新页面 / 断线重连都不能再联网**；
4. 低频入口不要占地方：上传、背景、清除、版本号都收进顶栏菜单（集群常用，留在外面）。

## 二、缓存分三层，各管一段

| 层 | 存什么 | 为什么放这里 |
|----|--------|--------------|
| localStorage | 开关、模糊度、亮度 | 只有几十字节，同步读取，页面首帧就能应用滤镜 |
| IndexedDB | 图片二进制 Blob | localStorage 只有 ~5MB 且只能存字符串，照片根本放不下 |
| relay 磁盘缓存 | 同 URL 的图片字节 + `{url,mime,ts}` 元数据 | 跨域图床浏览器拿不到，只能服务端代下；服务端落盘后同机房/同实例复用 |

前端的「下次不用重新拉」靠 IndexedDB：加载页面时先读 `assets/current`，命中就直接
`URL.createObjectURL(blob)` 挂到背景层，**一个网络请求都不发**。面板会显示"已从本地
缓存恢复（未联网）"，方便真机确认。

一个容易写错的点：`blob:` URL 只在当前文档生命周期有效，刷新后必须重新从 IDB 读、
重新 create。切换图片时旧 objectURL 不 `revokeObjectURL` 会一直占内存，所以每次
`bgSetImage()` 都先 revoke。

## 三、图从哪来：直连优先，代理兜底

```
用户填 URL
  ├─ fetch(url, mode:'cors')           ← 同源/CORS 放行的图床，最快
  │    成功 → 写 IndexedDB → 用 blob
  └─ 失败（CORS/网络）
        └─ GET /api/bg?url=...         ← relay 代下载 + 磁盘缓存
             成功 → 写 IndexedDB → 用 blob
             失败 → 直接外链显示，明确提示"下次仍需联网"
```

为什么不能只靠浏览器：`<img>` 显示跨域图片不受限制，但页面 JS **读不到**它（canvas
污染），也就没法写进 IndexedDB。所以跨域图床必须由 relay 代下载一次，之后前端缓存
才成立。

`/api/bg` 的约定：

- `GET /api/bg?url=<urlencoded>&refresh=1`，成功 `200 + image/* + X-Bg-Cache: hit|miss`；
- 参数缺失/非法 scheme → 400；目标解析到内网 → 403；下载失败/非图片/超限 → 502；
- 缓存目录 `WSSTUNNEL_BG_CACHE` 优先，否则 `~/.wsstunnel/bg-cache/`，文件名 `sha256(url)`；
- 只接受 `image/*`、8MB 上限、8s 超时、最多 3 次重定向且**每一跳都重新做 SSRF 校验**。

「↻ 重新拉取」按钮带 `refresh=1`：跳过服务端缓存强制重下并覆盖，前端同时覆盖 IDB，
用来应对"图床换了图但 URL 没变"。

## 四、渲染：xterm 透明化踩到的三个坑

背景图不是铺在终端下面就能看见，xterm 是 canvas 画的，默认整块不透明。

**坑 1：`allowTransparency` 只能在构造 Terminal 时给。**
它是构造选项，运行期改 `term.options.allowTransparency` 无效。所以统一构造时开，
只在 `theme.background` 上做开关（`'#1a1a2e'` ↔ `'rgba(0,0,0,0)'`）。

**坑 2：`.xterm-viewport` 自带黑底。**
`xterm.css` 给 viewport 画了 `background-color: #000`，即使 canvas 透明，图也被这层
黑底挡住。必须显式：

```css
#terminal .xterm-viewport { background-color: transparent !important; }
```

**坑 3：模糊之后四周露底。**
`filter: blur(Npx)` 会把图片边缘向外晕开，贴边的 `inset: 0` 会在四周露出 body 底色。
改成 `inset: -28px` 让图先放大出画布，再模糊，边缘永远在视口外。

层级顺序也固定下来：`#bg-layer`（z-index 0）→ `#terminal` / `#connect-form`（z-index 1）
→ 各类面板（30+）。截图验证时还顺手修了连接表单页面：它原来没定位，会被 fixed
背景层盖住。

## 五、一个测试环境才会遇到的坑：代理 fake-IP

relay 的 SSRF 防护会解析域名并拒绝私网地址。本机（Clash / Surge 类代理）实测：

```
picsum.photos → 198.18.4.174
www.google.com → 198.18.1.112
```

`198.18.0.0/15` 是 RFC 2544 benchmark 保留段，Python 的 `is_private` 把它判成私网，
于是 `/api/bg` 一律 403 —— **开着代理的机器上背景图代理直接全废**。

但这段地址现实中没有真实设备使用，放行它不构成内网 SSRF：连接实际由本地代理软件
接管，真正的内网段（10/8、127/8、169.254/16、100.64/10 等）仍然全部拦截。于是加
`_BG_FAKE_IP_NET` 白名单特例，并在测试里锁死"198.18 放行、其它私网仍拒绝"。

> 另一个环境差异：httpx 默认 `trust_env=True`，只认 `HTTP(S)_PROXY` 环境变量，
> 不读 macOS 系统代理。本机验证代理路径时需要显式给 relay 进程加环境变量，
> 否则 httpx 直连 fake-IP 会 8s 超时 —— 真实 VPS 没有这个问题，属于本机特例。

## 六、菜单收纳

顶栏从「状态 + 版本 + 集群 + 上传 + 背景」变成：

```
[已连接 ↑12s]            [📊 集群] [☰]
                          ├─ 📁 上传文件
                          ├─ 🖼 背景设置
                          ├─ ──────────
                          ├─ 🧹 清除连接配置
                          └─ 版本 v1.0.15
```

- 集群是高频操作（切后端、看状态），留在顶栏；
- 上传、背景、清除、版本号都是偶发，收进菜单；底部那个 fixed 的「清除」按钮删除；
- 菜单项点击后先 `menuClose()` 再执行动作，否则菜单还挂在屏幕上挡住终端；
- 背景菜单项的语义是**打开**面板而不是 toggle —— 点 ☰ 时 `stopPropagation` 让背景面板
  保持打开，再点菜单项若 toggle 会把它关掉，这是实测发现的一个小 bug。

## 八、取舍与遗留

- **DNS rebinding TOCTOU**：校验时解析一次、httpx 连接时再解析一次，恶意 DNS 理论上
  可绕过。彻底修法是"解析后钉 IP 直连 + 显式 Host/SNI"，当前未做——该端点只把图片
  返回给浏览器，不把响应体交给攻击者，利用面有限；注释里写明了加固方向。
- **缓存无 TTL**：只由 `refresh=1` 失效。图片一般不变，够用；要按时间过期的话元数据
  里已经存了 `ts`。
- **localStorage 写盘**：滑块拖动每帧写一次太浪费，做成 200ms 防抖；松手时 `change`
  再强制落盘一次。
- 背景图对终端文字可读性的影响交给亮度滑块（最小值压到 20%），不额外加遮罩层，
  避免二次调参。

**升级提示**：本次改了 `web/index.html` 且页面由 relay 内嵌分发，真机需**升级 relay
并强刷页面**；右上角菜单里的 `v1.0.15` 可用于确认加载的版本。

## 九、补丁：字体颜色（v1.0.16）

背景图最大问题是"图一亮，终端文字就看不清"，只调亮度是拿图片妥协。v1.0.16 把
**终端文字颜色**也做成可调项：

- 面板新增原生 `<input type="color">` + 5 个预设色块（浅灰 #e0e0e0 / 纯白 / 绿 / 黄 / 青）
  + 「默认」按钮；
- 改的是 xterm `theme.foreground`，运行期直接赋值 `term.options.theme` 即可生效，
  不像 `allowTransparency` 那样必须重建 Terminal；
- 颜色和开关/模糊/亮度一起存 localStorage（`fg` 字段），`#rrggbb` 正则校验，
  脏数据回落到默认值；刷新、重连都会恢复；
- 换色时保留背景透明判断：`bgApplyTerminalTheme()` 同时合并 `foreground` 与
  `background`，避免改色把背景透明性覆盖掉。

验证：点绿色预设 → `term.options.theme.foreground` 立即变 `#50fa7b`，prefs 落盘；
取色器改成 `#f1fa8c` 实时生效；刷新后取色器与连接后的终端文字颜色都恢复为 `#f1fa8c`。
